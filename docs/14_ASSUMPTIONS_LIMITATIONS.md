# Assumptions, Limitations and Ethics

## Assumptions

- The hero request represents a high-value purchase exception.
- Procurement and finance roles are sufficient for the first workflow.
- The CSV purchase history is authoritative for the synthetic scenario.
- MockDesk represents a ticketing integration, not a real enterprise system.

## Limitations

- No real customer discovery was conducted.
- No live SkyStudio workspace was used.
- Demo-header authorization is not production identity.
- Lexical document selection is not a complete enterprise RAG pipeline.
- Pattern detection is not a complete prompt-injection defense.
- SQLite audit storage is not immutable.
- Docker configuration was not executed in the package-generation environment because Docker was unavailable there.

## Ethical boundary

- The system does not autonomously approve purchases.
- A human owns the financial approval.
- Synthetic metrics are not presented as customer outcomes.
- Real customer or employee data must not be added to a public repository.
- Supplier-provided content is treated as untrusted.
- Model-generated explanations must not obscure deterministic decision inputs.
